## 零、开工携带清单（目标项目初始化）

本协议是**作者侧 QA 文档**，不随 `.agents/` 技能目录自动携带。在独立项目里做 dogfood 时，初始化清单：

1. **技能快照**：把 `.agents\skills\aidlc-workflows\` 拷贝到目标项目的 `.agents\skills\aidlc-workflows\`（保持原样，**不要往里加文件**——快照要和源 commit 一一对应）。
2. **快照 STAMP 惯例**（B12 挂账④，2026-10-20 落地）：记录表备注行固定格式 `source-commit: <hash> | snapshot-stamp: <YYYY-MM-DD HH:MM>`——时间戳取快照当刻（可 `python <skill>/scripts/engine.py stamp` 取权威值）。**副本记录卫生**：目标项目里的 `dogfood-protocol.md` 副本与各记录表属于目标项目产物——只随周期证据包归档回本仓库 `docs/dogfood-records/<项目名>/`，永不回写源仓库技能快照（`.agents/` 内零新增文件），永不反向修改本协议源文件。
3. **本协议**：把本文件拷贝到目标项目根目录（`dogfood-protocol.md`）——目标会话的模型按 §七 模板填表时需要读它。
4. **git**：目标项目 `git init` 并做首次提交（README 即可）。
5. **记录表归集**：各会话的表先随手存在目标项目里；周期结束后随证据包（aidlc-docs/ 全目录 + git log + 记录表 + 主观笔记）带回**本仓库** `docs/dogfood-records/<项目名>/` 供验收。
6. **迭代边界快照刷新规则**（B19，2026-10-20）：当后续迭代的验证目标包含新落地的技能 commit 时，允许在**迭代边界**刷新技能快照——从本仓库重新拷贝 `.agents\skills\aidlc-workflows\`，并在新迭代的记录表记新 STAMP 行（source-commit = 新收口提交）。刷新只发生在迭代边界，迭代进行中不换快照；刷新时目标项目的 `dogfood-protocol.md` 副本同步替换（新专项观测项需要新表）。

## 一、六条通用度量

逐条给出：度量名 / 定义 / 数据源 / 记录方式。这是 B05 时代的通用质量层，长期有效；当批专项观测见 §二/§三/§四。

### 1. 重复解释次数

- **定义**：同一会话或跨会话中，模型要求用户重复提供已有信息的现象。
- **数据源**：audit.md 条目趋势——重复解释通常伴随澄清类条目增多。
- **记录方式**：趋势观测（条目数随周期的升降），非精确计数。

### 2. PRD 范围清晰度

- **定义**：requirements.md 中观测边界与非目标声明的表述质量（是否显式声明、是否可证伪）。
- **数据源**：requirements.md 本体（人工阅读）。
- **记录方式**：**定性项**。不新增 RA 模板节，仅在 dogfood 记录表中做定性评注。

### 3. 硬门返工（原"重复评审"，2026-10-20 随 B18 重定义）

- **定义**：硬门（PB / RA / 完成仪式）被 Request Changes / 要求修订的重复次数。
- **数据源**：rejected / revised 转移趋势——engine status 的 recent_events 可直接观测。
- **记录方式**：按门计数（每周期累计）。**简报阶段无审批语义**——其转移条目出现 reject/revised 或任何等待-批准形态即属异常，改记入"异常与备注"行；无硬门的周期（如 express 走查）记 **N/A**。（原"自主模式会话记 N/A"条款随 D22 AM 退役移除。）

### 4. 换工具稳定

- **定义**：不同 harness / 编辑器会话之间，工作流行为是否一致。
- **数据源**：引擎 JSON 输出一致性（同状态输入 → 相同 status 字段输出）。
- **记录方式**：切换 harness 的会话中记录一致 / 不一致及差异点。单 harness 周期记 **N/A**；跨 harness 样本需主动安排（同一状态文件 + 异构 harness 的恢复会话），不会自然出现。

### 5. 新人首任务独立完成

- **定义**：无历史上下文的会话，能否仅凭技能文件 + status 恢复简报（resume_note / recent_events / artifact_alerts）接续工作。
- **数据源**：恢复会话的实际行为表现。
- **记录方式**：**定性项**，按三档记录：能 / 需人工干预 / 失败。

### 6. RCA bug 沉淀率

- **定义**：根因分析（RCA）结论转化为持久规则 / 文档的比例。
- **数据源**：RCA 记录与 docs/ 落地物对照。
- **记录方式**：**Phase 5A 知识树落地后生效**；当前周期仅记录 RCA 发生次数。

## 二、B18 门姿态专项观测（2026-10-20 增补·首次实弹）

**背景**：B18（D22/D23）后默认姿态 = 简报制 + 四硬门（PB / RA / 方向停点 / 完成仪式）+ 事件召唤。其中只有 PB/RA 是引擎硬门，其余全部为**规则级**——无引擎强制、无专用审计事件，**本节观测即其验收手段**（test_rule_invariants 只能证规则句存在，不能证遵守）。

| # | 观测点 | 判据 | 违规记录 |
|---|---|---|---|
| G1 | 简报纪律（BRF-01~03） | 完成简报 ≤5 行；含关键决策 / 风险 / 文件指针；零批准请求语 | 异常行，附简报实际行数与措辞 |
| G2 | 方向停点（code-gen 每轮首单元前，B18 ⭐2） | 每轮发生一次；≤10 行方向简报（单元数 / 顺序 / 风险）；用户实际用作换向 / 换模型 / 纯确认均可 | **静默跳过 = 红线** → 决策回填① |
| G3 | Stage Question Posture | 简报阶段自动答附带 rationale（推荐项 + 理由 + 回写）；拿不准的、产品 fork（含 extension-mandated 决策点，如 resiliency User Decision Points）必须升级问人；硬门阶段问题问人 | 该升未升 / 不必答而问人，均记异常行 |
| G4 | commit 授权问句 | build-and-test 末以显式问句请求授权（执行提交 / 用户自提交 / 暂不提交三选） | **自动 commit = 红线** |
| G5 | 审计真实性 | `approved` 语义仅出现于 PB / RA / 完成仪式相关条目；简报阶段转移条目为 completed 直转 | 任何简报阶段的批准形态 = 假批准，异常行 |
| G6 | WP 偏差升问句（B18 ⭐3，fork 升级第一应用点） | 计划结构性偏差（增删阶段 / scope / depth 变更）升显式问句，不静默改计划 | 静默改计划 = 异常行 |

## 四、B19 reviewer 前置接线专项（2026-10-20 增补）

迭代二起适用（快照源 = B19 收口提交）。三位置 = RA 门材料前 / 方向门简报前 / B&T 收尾简报前（阶段 frontmatter `review_class` 声明；机制与纪律见技能 `references/common/review-delegation.md`）。**R1/R5/R7 为红线组**（同 G 组纪律：违规必须显式记录，不得静默放过）。

| ID | 观察点 | 判据与记录方式 |
|---|---|---|
| R1 | 未提示即委派（锚点被静默跳过——与 G2 同型观测）**〔红线〕** | 三位置各至少一条 reviews.md R 条目；任一位置缺失且制品已过门 = 红线，异常行记录 |
| R2 | 降级链档位分布 | R 条目 tier 字段计数：①专职评审 agent / ②通用委派 / ③专家档 / ④self-review (degraded) / review unavailable |
| R3 | 阻塞 finding vs 噪声 | 被驳回 finding 占比（triage 出口计数）；注：被证伪占比需跨迭代数据（存活率回灌属 5B），单周期只记被驳回 |
| R4 | 三位置存在感 | 定性一行/位置：哪位置的 finding 实际改变了制品或决策、哪位置最可省 |
| R5 | 会话纪律（每次审查全新会话）**〔红线〕** | R 条目 session 字段可核对（harness 句柄或 fresh+时间戳）；发现复用/续用审查会话 = 红线 |
| R6 | 轮次预算 | round 字段 ≤3；用尽 3 轮升级 fork 的案例全文记录 |
| R7 | not-covered 诚实性（能力条件化）**〔红线〕** | code-quality 审查的执行依赖维度标注与 reviewer 实际工具能力一致；"没审装审"或把 not-covered 报成已核 = 红线 |
| R8 | 成本与档位 | 单次审查耗时（委派→返回）+ 实际模型档（design-soundness 是否配了强档） |

## 六、消融对照

- **历史对照**：Phase 3（引擎落地）前后的 dogfood 记录对比。基线 = docs/batches/ 各批次档案中的历史 dogfood 记录与既有 dogfood 体验（2026-09-14 裸项目、2026-09-15 course-schedule）。

- **门姿态前后对照（2026-10-20 增补）**：AM 时代 dogfood 记录（fx991 三迭代、b15 档案 dogfood #1/#2）为历史基线；B18 后周期对比观测三项——真门实际次数、假批准清零情况（G5）、用户注意力分布（实际花时间读的是哪些门的材料）。
- **显式声明**：无引擎臂（完全脱离 engine.py 的工作流）在当前契约下**不可构造**——引擎是必选运行时组件（决策 D6，无引擎 = HARD STOP），且跨阶段路由仅由引擎 `next` 提供（Only-next-routes）。此为永久约束，除非契约变更。

## 七、数据源

- **首选**：audit.md 审计条目（append-only，含转移条目与用户输入记录）。
- **引擎侧**：`engine.py status` 输出的 `audit_entries` / `audit_bytes` 字段（B04 起），以及 resume_note / recent_events / artifact_alerts。
- **观测记录**：本协议 §八 的一次一表。
- **门姿态专项（§二）**：G2 / G3 / G6 无引擎事件，以会话实际行为 + 制品核对（简报文本、问题文件、计划行、git log）为准；G5 以审计条目形态为准。
- **reviewer 专项（§四）**：`aidlc-docs/reviews.md` 的 R-n/T-n 条目全字段（tier/model/session/round/findings/not-covered/triage）+ 会话实际委派行为。
- **注意**：数据读取遵循分级阅读纪律（session-continuity.md），不做全量加载。

## 八、记录模板（一次一表）

| 度量 | 观测值 | 备注 |
|---|---|---|
| 1. 重复解释次数 | <趋势：升/平/降 + 条目数估计> | |
| 2. PRD 范围清晰度 | <定性评注：显式性 / 可证伪性> | |
| 3. 硬门返工 | <门名：次数> | |
| 4. 换工具稳定 | <一致 / 不一致 + 差异点> | |
| 5. 新人首任务独立完成 | <能 / 需人工干预 / 失败> | |
| 6. RCA bug 沉淀率 | <本周期 RCA 次数> | |

| 10. B20 规则层精简走查（§五 C1~C2） | <通过项 / 异常项；未触发硬门记 N/A> | |

- **软警告观测**：produces_missing 出现 <N> 次；处置：<按 action_discipline 报告用户后用户如何决定 / 未出现>

模板末行（**决策回填**）是本协议的核心机制：当期挂起的遗留决策靠各周期回填行累积证据（首例：produces_missing 升级议题，经 2026-09-24 验收裁决与 fx991 三迭代累计 5 周期零触发后关闭）。

**当前挂账的待裁决项**：

1. **B18 方向停点引擎化**（G2）：⭐4 裁决采用规则级停点，代价声明——若 dogfood 观察到被静默跳过，回填本项并升级为引擎机制（届时动引擎，属新批）。
2. 通用通道照旧——新出现的候选决策按"无待裁决项，无新证据"或一句话启示记录。

## 九、纪律

- 记录本身不阻塞工作流（advisory 性质）——度量采集不得干扰 Orchestration Loop 与门仪式。
- **门姿态红线违规（G2 静默跳过 / G4 自动 commit / G5 假批准）必须在异常行显式记录，不得静默放过**——红线观测正是本协议对 B18 的核心价值。
- **审查红线违规（R1 静默跳过审查 / R5 复用审查会话 / R7 not-covered 谎报为已核）同样必须在异常行显式记录**——B19 的核心观测即纪律本身；reviews.md 是 append-only 证物，观测时只读不改。
- 每个 dogfood 项目结束时，在 docs/ 下另存一份填好的表，命名约定：`dogfood-records/<项目名>-<日期>.md`（如 `dogfood-records/course-schedule-2026-09-22.md`）。
- 度量不用于考核模型，只用于改进技能与引擎设计。
