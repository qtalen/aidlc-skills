# Dogfood 度量协议

本协议服务于 Phase 3.1（会话连续性：park / 恢复简报 / 传感器 / 软警告）落地后的**首个 dogfood 周期**。目标：把"感觉有用"变成可记录的观测，为后续决策提供数据——最直接的一项是 produces_missing 软警告是否升级为硬阻断（Phase 3.1 遗留决策，见 integration-plan.md §7）。

---

## 零、开工携带清单（目标项目初始化）

本协议是**作者侧 QA 文档**，不随 `.agents/` 技能目录自动携带。在独立项目里做 dogfood 时，初始化清单：

1. **技能快照**：把 `.agents\skills\aidlc-workflows\` 拷贝到目标项目的 `.agents\skills\aidlc-workflows\`（保持原样，**不要往里加文件**——快照要和源 commit 一一对应）；在记录表备注里写明源 commit。
2. **本协议**：把本文件拷贝到目标项目根目录（`dogfood-protocol.md`）——目标会话的模型按第四节模板填表时需要读它。
3. **git**：目标项目 `git init` 并做首次提交（README 即可）。
4. **记录表归集**：各会话的表先随手存在目标项目里；周期结束后随证据包（aidlc-docs/ 全目录 + git log + 记录表 + 主观笔记）带回**本仓库** `docs/dogfood-records/<项目名>/` 供验收。

## 一、六条度量

逐条给出：度量名 / 定义 / 数据源 / 记录方式。

### 1. 重复解释次数

- **定义**：同一会话或跨会话中，模型要求用户重复提供已有信息的现象。
- **数据源**：audit.md 条目趋势——重复解释通常伴随澄清类条目增多。
- **记录方式**：趋势观测（条目数随周期的升降），非精确计数。

### 2. PRD 范围清晰度

- **定义**：requirements.md 中观测边界与非目标声明的表述质量（是否显式声明、是否可证伪）。
- **数据源**：requirements.md 本体（人工阅读）。
- **记录方式**：**定性项**。不新增 RA 模板节，仅在 dogfood 记录表中做定性评注。

### 3. 重复评审

- **定义**：同一阶段被 Request Changes 的重复次数。
- **数据源**：rejected / revised 转移趋势——engine status 的 recent_events 可直接观测。
- **记录方式**：按阶段计数（每周期累计）。

### 4. 换工具稳定

- **定义**：不同 harness / 编辑器会话之间，工作流行为是否一致。
- **数据源**：引擎 JSON 输出一致性（同状态输入 → 相同 status 字段输出）。
- **记录方式**：切换 harness 的会话中记录一致 / 不一致及差异点。

### 5. 新人首任务独立完成

- **定义**：无历史上下文的会话，能否仅凭技能文件 + status 恢复简报（resume_note / recent_events / artifact_alerts）接续工作。
- **数据源**：恢复会话的实际行为表现。
- **记录方式**：**定性项**，按三档记录：能 / 需人工干预 / 失败。

### 6. RCA bug 沉淀率

- **定义**：根因分析（RCA）结论转化为持久规则 / 文档的比例。
- **数据源**：RCA 记录与 docs/ 落地物对照。
- **记录方式**：**Phase 5A 知识树落地后生效**；当前周期仅记录 RCA 发生次数。

## 二、消融对照

- **历史对照**：Phase 3（引擎落地）前后的 dogfood 记录对比。基线 = integration-plan.md §9 历史记录与既有 dogfood 体验（2026-09-14 裸项目、2026-09-15 course-schedule）。
- **引擎内开关对照**：park 与 produces_missing 软警告均为引擎内置行为，可在不同 dogfood 会话中分别启用 / 禁用相关流程纪律，做近似对照。
- **显式声明**：无引擎臂（完全脱离 engine.py 的工作流）在当前契约下**不可构造**——引擎是必选运行时组件（决策 D6，无引擎 = HARD STOP），且跨阶段路由仅由引擎 `next` 提供（Only-next-routes）。此为永久约束，除非契约变更。

---

## 三、数据源

- **首选**：audit.md 审计条目（append-only，含转移条目与用户输入记录）。
- **引擎侧**：`engine.py status` 输出的 `audit_entries` / `audit_bytes` 字段（Phase 3.1 起），以及 resume_note / recent_events / artifact_alerts。
- **观测记录**：本协议第四节的一次一表。
- **注意**：数据读取遵循分级阅读纪律（session-continuity.md），不做全量加载。

## 四、记录模板（一次一表）

每个 dogfood 会话填一张表：

```markdown
## Dogfood 记录：<项目名> — <会话日期>

- **会话日期**：YYYY-MM-DD
- **harness**：<工具名 / 编辑器>
- **工作流阶段**：<当前阶段 slug / 跨阶段说明>

| 度量 | 观测值 | 备注 |
|---|---|---|
| 1. 重复解释次数 | <趋势：升/平/降 + 条目数估计> | |
| 2. PRD 范围清晰度 | <定性评注：显式性 / 可证伪性> | |
| 3. 重复评审 | <阶段：次数> | |
| 4. 换工具稳定 | <一致 / 不一致 + 差异点> | |
| 5. 新人首任务独立完成 | <能 / 需人工干预 / 失败> | |
| 6. RCA bug 沉淀率 | <本周期 RCA 次数> | |

- **异常与备注**：<本次会话的异常、偏离契约的行为、意外发现>
- **软警告观测**：produces_missing 出现 <N> 次；处置：<按 action_discipline 报告用户后用户如何决定 / 未出现>

**决策回填**：本周期观测对"软警告是否升级硬阻断"等遗留决策的启示：<一句话结论或"无新证据">
```

模板末行（**决策回填**）是本协议存在的核心目的：Phase 3.1 遗留的"软警告待 dogfood 后议升级"决策，靠各周期回填行累积证据。

---

## 五、纪律

- 记录本身不阻塞工作流（advisory 性质）——度量采集不得干扰 Orchestration Loop 与门仪式。
- 每个 dogfood 项目结束时，在 docs/ 下另存一份填好的表，命名约定：`dogfood-records/<项目名>-<日期>.md`（如 `dogfood-records/course-schedule-2026-09-22.md`）。
- 度量不用于考核模型，只用于改进技能与引擎设计。
